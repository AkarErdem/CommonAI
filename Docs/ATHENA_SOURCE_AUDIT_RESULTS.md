# AthenaAI source audit results

## Reference and installed versions

- Behavioral reference: `Docs/AthenaAI_Manual/Athena_AI_Manual.md`, local version 2.6, especially §§2, 3, 5, 6.1–6.9 and 7. Its adjacent media remains local.
- Installed runtime: AthenaAI descriptor version 2.6 for Unreal 5.8; one Runtime module, `AthenaAI`. The current CommonAI descriptor and Build.cs both name the `CommonAI` Runtime module and depend downward on `AthenaAI`. The local Editor compile used Win64 and Visual Studio toolchain 14.44.35219.
- Native API evidence below is from the installed `Plugins/AthenaAI/Source/AthenaAI` tree. It establishes declarations and implementation behavior, not an independent-host portability result.

| Area | Source evidence | Conclusion |
|---|---|---|
| Component and manager | `Public/AthenaAIComponent.h`: exported `UAthenaAIComponent`, virtual `Initialize`, `InitializeDataManager`, `CreateDataManager`; `Private/AthenaAIComponent.cpp`: `CreateDataManager` calls `NewObject<UAthenaAIDataManager>(this, ...)`, then `InitializeDataManager` calls `Initialize`. | A derived component has a supported manager factory override. No manager replacement is needed by the first slice; the factory's derived runtime type has not been tested. |
| Preset and instances | `Public/AthenaAIAgentPreset.h`: exported data asset with instanced Tasks, Services and fallback; `Private/AthenaAIComponent.cpp`: `ConfigureTasks` and `ConfigureServices` duplicate templates into each component. | Preset definitions are shared; runtime Task/Service instances are per component. Actions are instanced members of a duplicated Sequence Task. |
| Task | `Public/AthenaAITask.h`: exported virtual `Initialize`, `Start`, `Stop`, `Cleanup`, `AbortTask`, `FinishTask`; `Private/AthenaAITask.cpp` calls the Blueprint start/termination events and notifies the component. | Native Wait/Work subclasses are supported. A task instance can be started again and must reset transient state. |
| Sequence and Action | `Public/AthenaAITask_Sequence.h`, `Public/AthenaAIAction.h`: exported virtual lifecycle methods; `Private/AthenaAITask_Sequence.cpp`, `Private/AthenaAIAction.cpp`: Actions run in array order and advance through `FinishAction`/`NotifyActionStopped`. | Native sequence/action subclasses are supported. `StartAction(0)` runs before the sequence sets its running flag; a synchronous first completion is ignored. CommonAI defers action completion to the next tick and makes action cleanup idempotent. |
| Service and evaluator | `Public/AthenaAIService.h`: exported virtual `Initialize`, `StartService`, `StopService`, `ServiceTick`; `Public/AthenaAIConsiderationEvaluator.h`: `UAthenaAIConsiderationEvaluator` lacks `ATHENAAI_API`, while `CanEvaluate` is out of line. | Native Service extension is source-feasible. External native Evaluator inheritance is unresolved at the DLL boundary and is not used in this slice. |
| Behavior Tree Task | `Public/AthenaAITask_BTBase.h`: exported subclass with `StopBT`; manual §6.8 warns it replaces the controller's active Behavior Tree. | Omitted to preserve existing controller behavior. |
| Scoring and fallback | `Private/AthenaAIDataManager.cpp`: consideration curves multiply, then Score Modifier and Momentum apply; Priority resolves ties, including a random equal-priority tie. `CanReplaceCurrentTask` uses the current task's required override score. | Use Athena's scorer, resistance, locking and fallback. No parallel scorer or routine selector is added. An authored Curve Table is required for normal scoring. |
| Evaluator gating and normalization | `Private/AthenaAIDataManager.cpp`: `EvaluateConsideration` calls `CanEvaluate`, then `ShouldEvaluate` and `CalculateRawValue`; false gating skips the update. `GetNormalizedValue` uses the configured min/max range. | A skipped evaluation retains the previous consideration value. Consumers must provide valid ranges and explicitly clear eligibility when inputs become unavailable; this first slice does not add an evaluator. |
| Service lifecycle | `Public/AthenaAIService.h`, `Private/AthenaAIService.cpp`: conditions start/stop the service, `StartService` uses a timer, `StopService` clears its latent actions and timers. | Existing service timing is available for later observations. No service subclass is needed for the first Work activity. |
| Tag and curve names | `Public/AthenaAITask.h`, `Public/AthenaAIAction.h`, `Public/AthenaAIDataManager.h`: plural tag filters; `Private/AthenaAIAgentPreset.cpp`: shorteners 15/17/24 and `Task - Consideration` row names. | The plural `AthenaAI.Tasks`, `AthenaAI.Actions`, `AthenaAI.Considerations` forms are the native convention; some singular manual examples are inconsistent. |
| Termination | `Private/AthenaAIComponent.cpp`: `StopAILogic` stops the active task with `Successful`; `Private/AthenaAITask.cpp`: termination notifies the component. Manual §2.4 describes the same result reuse. | Vendor `Successful` does not prove Work completion. CommonAI reports domain completion only after Perform, Release and actual sequence finish. |

## First-slice boundaries

CommonAI owns the typed execution context, opportunity/provider contract, exclusive site reservation, timed and signaled execution variants, Wait, generic Move, and the Work sequence. A consumer may attach the vendor component and CommonAI provider to an existing AIController and supply authored sites. The current host enables the plugin but changes no production controller or movement pipeline.

The default Move action uses the active AIController's path following request and aborts only its own request ID. Consumers with a separate movement authority must provide an adapter before enabling the Work task on those controllers. No authored preset, Curve Table, cooked asset or independent minimal-host verification is claimed here.

Both the Development Editor and non-editor Development Game targets compiled and linked the CommonAI runtime module in the authorized local host. Runtime construction, movement, cancellation and activity outcomes were not exercised in this iteration.
